Fixing Heightfield Terrain in Newton’s MuJoCo Backend

[Open source · merged]

With the MuJoCo solver, Newton collided against heightfield terrain about half a metre away from where it drew it, so objects came to rest floating above the ground. The fix is merged into Newton.

How I found it

While working with heightfield surfaces in Newton, I noticed objects resting above them. Newton’s own example showed the same thing, and I measured it: the spheres stopped 0.51–0.53 m above the drawn surface, almost exactly the depth of the terrain’s lowest point below its origin. That pointed at the conversion from Newton’s heightfield to MuJoCo’s.

The cause

MuJoCo measures a heightfield up from its origin, while Newton lets it go below. The converter accounted for this by shifting the terrain, but a kernel that re-syncs every shape’s pose, at construction and whenever shape properties change, overwrote the shift. A second, smaller bug: the terrain’s size ignored its scale. Existing tests missed both, because every MuJoCo heightfield test started at zero height, and the example only ran in CI with a different solver.

The fix

  • Compute each heightfield’s offset once and re-apply it inside the re-sync kernel, the way the code already handled meshes. It needs no reads back to the CPU, so the update still works inside a CUDA graph.
  • Apply the scale to the terrain size, and shift along the terrain’s own axis, which matters once it is rotated.
  • Four new tests: a sphere must settle at the bottom of a bowl below the origin, a rotated and scaled terrain must keep its size and pose after updates, and the update must be capturable in a CUDA graph. The first two fail before the fix and pass after it.

The pull request: newton-physics/newton #4410.
